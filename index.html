Element 01  ·  The Foundational Concept, Not the Grade-Level Skill
What Lies
Beneath
The game teaches the simpler underlying idea — the prerequisite that makes the harder skill make sense. A 7th-grade game about proportional relationships might actually be teaching “what a ratio means physically.” This separation is a deliberate choice every time.
Mathly
Element 02  ·  The Mechanic IS the Aha Moment
Where the Light
Comes From
Not “test whether students got it” — recreate the experience of getting it. The game’s visual world and core interaction should feel like the teacher’s best classroom moment, made physical. If the aha moment was folding paper into eighths, the game puts that experience in the student’s hands.
Mathly
Element 03  ·  Wrong Answers Are Designed, Not Default
Every Decoy,
Deliberate
Misconceptions are researched and named before a line of code is written. Wrong-answer choices mirror the specific faulty mental model students arrive with. The game confronts the error pattern directly — it never routes around it.
Mathly
Element 04  ·  Failure Is an Instructional Sequence
Guided,
Not Lost
Three progressively direct hints, each visual, each using different numbers, each building on the last. Getting it wrong isn’t a verdict — it’s the beginning of a teaching moment. The Unstuck Playlist catches what the game can’t.
Mathly
Element 05  ·  One Change Per Level
One Turn
at a Time
Each level makes exactly one change. Scaffolds are removed most-supportive-first. Complexity increases one step. Students never lose two supports at once — they always know what changed.
Mathly
Element 06  ·  Visual Does the Heavy Lifting
The Screen
Speaks First
Every instruction, hint, and piece of feedback is shown, not told. Text is capped at 1st-grade reading level and plays a supporting role. A student who can’t read the words should still understand what to do by watching the screen.
Mathly
Element 07  ·  Designed for Marcus
Built for
This Kid
Every barrier that isn’t the math itself is removed: no timer, no drag-and-drop, no reading-heavy UI, optimized for the Chromebook on his desk. Marcus isn’t an abstract 7th grader — he’s a specific student, and the game knows it.
Mathly
Element 08  ·  It Knows Its Place in a Larger System
Part of Something
Larger
Games fire completion handshakes, trigger the Unstuck Playlist, and hand off gracefully. They don’t end on a fade-out — they end on a signal that our platform catches and responds to.
Mathly
Element 09  ·  It’s a First Encounter, Not a Review
As If for
the First Time
Every skill is treated as a beginner skill. The game is designed for curiosity and discovery, not consolidation of prior knowledge. It never assumes the student has seen this before — even if the curriculum has technically covered it.
Mathly
Element 10  ·  The Game Has a Definitive End
The Threshold
Is Earned
15–20 problems, roughly 3 per level. The game ends automatically and fires a handshake. The student doesn’t get to decide they’re done — the game does. This is not an endless practice loop. It’s a designed experience with a beginning, middle, and end.
Mathly
Element 11  ·  The Mechanic Is Derived from the Concept
Made for
Each Other
Most ed-tech games bolt curriculum onto an existing format — match, drag, quiz. The mechanic is generated from the aha moment. It exists because of what needs to be understood, not because it’s a proven engagement pattern. You couldn’t swap it into a different skill.
Mathly
Element 12  ·  Game Length Is Derived from the Pedagogy
Structure
Follows Learning
Total levels = complexity levels + number of scaffolds removed. The game’s structure is calculated, not chosen. How long it is follows directly from how much the student needs to learn and how much support they need to lose.
Mathly
Element 13  ·  Hints Preserve the Challenge
Just Enough
Light
Every hint uses different but similar numbers — never the same as the live problem. The hint teaches the concept without handing over the answer. Help is calibrated to close the gap, not eliminate it.
Mathly
Element 14  ·  Answer Choice Difficulty Scales
Judgment,
Not Guesswork
3 choices at the floor, 4 at mid, 4–5 at the ceiling. Wrong choices always mirror misconceptions at every level. The choice architecture is designed, not arbitrary — it evolves in parallel with the intellectual demands of the level.
Mathly
Element 15  ·  Pedagogy Owns the Design; Code Is Downstream
Vision
Comes First
The prompt tells Lovable what to build without specifying how. The teacher owns the learning design. Lovable owns the implementation. These are held apart intentionally — the vision leads, the execution follows.
Mathly
Element 16  ·  The Emotional History of the Student Is a Design Input
History in
the Hands
Marcus isn’t an archetype — he’s a specific student with a specific history. The emotional weight of having been made to feel like a failure in math class isn’t peripheral to the design. It’s the primary lens through which every decision is made.
Mathly
Element 17  ·  A Precise Pedagogical Artifact
Nothing
by Accident
Our games are precise pedagogical artifacts, not a content delivery vehicle. Every element — the mechanic, the progression, the hints, the wrong answers, the constraints, the length — is an expression of a specific theory about how this specific student learns this specific concept.
